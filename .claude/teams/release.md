# Release & Reliability Team

## Mission

Deliver change safely and keep production healthy against explicit SLOs and error budgets.

## Charter

- Progressive delivery: canary, monitor, automatic rollback.
- Every incident produces a blameless postmortem with tracked actions.
- Reliability work is prioritised by error budget burn, not opinion.

## Roster (5)

- [Release Manager](../agents/release-manager.md) — Get changes to production predictably, with the risk visible and the rollback ready.
- [Site Reliability Engineer (SRE)](../agents/site-reliability-engineer.md) — Keep production reliable against explicit SLOs while enabling fast change.
- [Incident Response Engineer](../agents/incident-response-engineer.md) — Detect, contain, and resolve incidents quickly, then make the same failure impossible.
- [Chaos Engineering Engineer](../agents/chaos-engineering-engineer.md) — Find weaknesses by injecting controlled failure into real systems before reality does.
- [Production Readiness Engineer](../agents/production-readiness-engineer.md) — Ensure nothing reaches production without ownership, observability, and an operational plan.

## How to engage

Delegate to a single agent with the Agent tool using its `name` from the roster above.
For work spanning several of these agents, start with the team's architect or lead,
get the design decision recorded, then fan out to implementers.
