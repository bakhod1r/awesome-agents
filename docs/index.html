Quick start

Three commands. No configuration, no dependencies beyond Python 3.

git clone https://github.com/bakhod1r/awesome-agents.git
cd awesome-agents
python3 scripts/generate.py   # regenerates .claude/ from scripts/agents_data.py

Open the folder in Claude Code and ask normally. CLAUDE.md loads automatically, Claude reads the roster and delegates to the right specialist. To force one:

Use the database-architect agent to review this schema.

Tutorial

1. The delegation chain

Architect decides. Engineer implements. Quality verifies. Release ships. Never skip a link. Implementation with no design decision produces rework; a release with no verification produces an incident.

3. Worked example

Shipping a payments retry mechanism, end to end:

/design payment retry with idempotency keys
  → backend-architect + integration-architect produce options and failure modes
  → decision written to docs/adr/0007-payment-retry.md

/team implement the retry design
  → backend-developer implements; database-engineer adds the idempotency table

/review
  → code-reviewer, application-security-engineer, api-quality-engineer
  → findings ranked by severity, each with a concrete failure scenario

/ship
  → production-readiness-engineer blocks until the runbook and rollback exist
  → release-manager defines canary gates and abort criteria

4. What every agent guarantees

All 109 agents carry the same ten sections — Role, Mission, Primary Objective, Responsibilities, Collaboration, Inputs, Outputs, Decision Rules, Quality Bar, Output Format — plus a shared operating standard:

  • Read the actual code, data, or telemetry before concluding. Never answer from memory about system state.
  • Label what was verified versus inferred.
  • Quantify. "Slow" is not a finding; "p99 480 ms against a 200 ms budget" is.
  • Deliver the whole scope. If part is blocked, finish the rest and name what was left out.
  • Escalate with a proposed decision, never a bare problem.

5. Standing rules

Applied to all work without being asked: engineering standard, security baseline, testing, documentation, data & privacy, agent authoring, output discipline.

Install as a plugin

This repository is also a Claude Code plugin marketplace — 17 plugins, one per team plus the shared workflow. Install only the teams you need.

/plugin marketplace add bakhod1r/awesome-agents
/plugin install agent-workflow@awesome-agents     # commands + skills
/plugin install security-team@awesome-agents      # that team's agents
/plugin install backend-team@awesome-agents

Extend

Agent and team files are generated. Edit the data, never the output.

# scripts/agents_data.py
dict(
    slug="graph-database-engineer", title="Graph Database Engineer", team="backend",
    model="sonnet", tools=FULL,
    mission="Design and operate graph stores for traversal-heavy workloads.",
    focus=[...],      # 5 responsibilities
    inputs=[...], outputs=[...],
    rules=[...],      # decision rules that would survive a design review
    bar=[...],        # what "done well" means, measurably
)
python3 scripts/generate.py   # rewrites .claude/agents/, .claude/teams/, docs/

Hand edits to .claude/agents/*.md are lost on the next run. That is deliberate — one source of truth means 109 agents stay consistent.

Writing a good agent

  • Decision rules must be opinionated. "Index to the query, not to the column" is a rule. "Follow best practices" is noise.
  • Quality bar must be checkable. "Restore drill passing within RTO", not "high quality".
  • Least privilege on tools. Architects and reviewers get read-only.
  • Model choice: opus for architecture, security, and judgement-heavy roles; sonnet otherwise.
